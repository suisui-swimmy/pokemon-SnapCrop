# pokemon-SnapCrop

`pokemon-SnapCrop` は、対戦画面のライブ映像をブラウザで見ながら、左右に自分側 / 相手側の参照画像を保持表示し、下段の CLI 風パネルでポケモン情報を引ける静的 Web アプリです。

## できること

- 映像入力デバイス一覧を表示して、キャプチャデバイスや OBS 仮想カメラを選択する
- 16:9 入力では左右クロップに固定プリセットを自動適用し、必要なときだけ `edit` で一時調整する
- `edit` / `ready` を切り替えながら、左右の参照画像を `snap both` で更新する
- `ready` 中だけ、`loading -> 選出タイマー -> 選出完了ラッチ -> 待機タイマー` の順序を小さいテンプレ照合で監視し、自動で `snap both` する
- 下段の CLI 風パネルでポケモン名を検索し、CSV からタイプ、特性、種族値を表示する
- 4:3 入力ではクロップ位置とサイズを `localStorage` に保存し、次回起動時に復元する
- PWA としてインストールしやすい最低限の構成で動かす
- OBS 仮想カメラの 16:9 入力を優先し、4:3 入力でも黒帯込みで補正して扱う

## ローカルでの起動方法

`file://` 直開きではなく、ローカルサーバー経由で開いてください。

- Visual Studio Code の Live Server など、任意の静的ファイルサーバーでこのフォルダを配信します
- 配信後、表示された `http://localhost:xxxx` を開きます

要点は「このリポジトリを HTTP 経由で配信すること」で、サーバーの種類は問いません。

## なぜ `file://` ではなくローカルサーバーが必要か

- `getUserMedia()` による映像入力は、基本的にセキュアコンテキストが必要です
- CSV は `fetch()` で読み込むため、`file://` 直開きだとブラウザ制約で失敗しやすいです
- Service Worker と PWA 登録も `file://` では正しく動きません

`localhost` または GitHub Pages のような HTTPS 配信を前提に使ってください。

## 映像デバイスの選択方法

1. ページを開く
2. `映像入力` からキャプチャデバイスまたは OBS 仮想カメラを選ぶ
3. 選択した時点で自動的に映像開始を試みます
4. 初回はブラウザの映像アクセス許可を求められるので許可する
5. 自動開始できなかった場合は `映像を開始` を押して再試行する

権限許可前はデバイス名が generic な表示になることがあります。許可後に `一覧更新` を押すと実デバイス名が見えやすくなります。
OBS Virtual Camera が見えている場合は、その入力を優先して使うのが推奨です。

## 左右クロップ領域の調整方法

- 16:9 入力では、起動時に自分側 / 相手側の固定クロッププリセットを自動適用します
- 16:9 入力では、そのまま `ready` で開始します
- 4:3 入力では、これまでどおり手動クロップを前提にします
- `edit` で編集モードに入ると、ライブ映像上に自分側 / 相手側の矩形が表示されます
- 矩形全体をドラッグすると移動します
- 右下ハンドルをドラッグするとサイズ変更します
- `X / Y / 幅 / 高さ` の数値入力でも微調整できます
- 編集中の左右プレビューは現在フレームに追従して更新します
- `ready` に戻るとライブ追従を止め、直近の参照画像を保持表示します

座標計算は表示サイズ固定ではなく、実際の `videoWidth / videoHeight` を基準にしています。
4:3 入力時は左右の黒帯を含む表示でも、実映像領域に合わせてクロップ座標を補正します。
16:9 入力で `edit` した内容はそのセッション中だけ有効で、次回は固定プリセットから始まります。

## CLI パネルの使い方

- 入力欄にはポケモン名だけを入れます
- Enter で実行します
- 検索は CSV 内の `ポケモン名` 列に対して完全一致優先です

主なコマンド:

- `edit`: クロップ範囲を編集する
- `e`: `edit`
- `ready`: 実戦モードに戻る
- `r`: `ready`
- `snap my` / `snap enemy` / `snap both`: 参照画像を更新する
- `s`: `snap both`
- `sm`: `snap my`
- `se`: `snap enemy`
- `auto on` / `auto off` / `auto status` / `auto reset`: 待機中画面の自動 snap を制御する。`auto on` は `ready` への切り替えまでまとめて行う
- `debug on` / `debug off` / `debug status`: 認識範囲のデバッグ表示を制御する
- `status`: 現在の mode / auto / debug / input / video / audio を要約表示する
- `clear` / `cls`: terminal の表示をクリアする
- `crop reset [my|enemy|both]`: クロップを初期状態に戻す

自動 snap の流れ:

- `ready` かつ `auto ON` の間だけ監視します
- まず右下の `読み込み中` を、固定 ROI 上で `loading-indicator.png` と照合して検出します
- 次に選出画面左上の時計アイコンを、別テンプレート `selection-timer-icon.png` と固定 ROI で照合して選出画面に入ったと判断します
- 中央上部の待機タイマーが見えた最初のフレームで `snap both` します
- 左端の番号帯と左下の `4/4` 完了バーによる `選出完了` ラッチは補助判定として残していて、主経路のテンプレ一致を邪魔しない safety gate として使います
- `loading` / `選出タイマー` / `待機タイマー` は、1920x1080 基準の固定 ROI とユーザー提供のテンプレート画像で判定します
- 自動 snap は 16:9 入力専用です。4:3 入力ではクロップ補正はできますが、自動認識は動きません
- fallback は待機タイマー候補を 1 度でも見た後だけ許可し、実 battle HUD が先に来たときだけ候補フレームを 1 回使います
- UI 上の認識範囲表示は `debug on` のときだけ出ます。普段は表示しません

ショートカット:

- 空入力 + Enter (`ready` 中): `snap both`
- `Ctrl + Enter`: `snap both`
- `Esc` (`edit` 中): `ready`

表示例:

```text
> ドラパルト
タイプ: ドラゴン / ゴースト
特性: クリアボディ / すりぬけ / のろわれボディ
種族値: H88 A120 B75 C100 D75 S142
```

## CSV の前提

同梱 CSV `data/champions_ Reg_M-A.csv` を読み込みます。実装では以下の実列名を確認して、そのまま利用しています。

- `ポケモン名`
- `タイプ1`
- `タイプ2`
- `H`
- `A`
- `B`
- `C`
- `D`
- `S`
- `とくせい1`
- `とくせい2`
- `とくせい3`

CSV の内容を勝手に推測せず、上記列の存在を読み込み時に検証しています。

## `localStorage` に保存する内容

- 4:3 入力で手動調整した自分側クロップ矩形の位置 / サイズ
- 4:3 入力で手動調整した相手側クロップ矩形の位置 / サイズ

保存時は現在の映像解像度に対する比率で保持し、次回起動時はその時点の映像サイズに合わせて安全に補正して復元します。
16:9 入力では固定クロッププリセットを毎回優先して適用するため、`edit` の調整結果は `localStorage` に保存しません。

## PWA について

- `manifest.webmanifest` と `sw.js` を含む最低限の PWA 構成です
- アプリシェルと同梱 CSV をキャッシュします
- ただし、カメラ機能がオフラインでも完全動作することを保証するものではありません
- 目的はオフライン完全対応ではなく、アプリ風に起動しやすくすることです

## GitHub Pages への公開方法

1. このリポジトリを GitHub に push する
2. リポジトリの Pages 設定で `GitHub Actions` をソースにする
3. `main` ブランチへ push すると自動で deploy が走る

相対パスで構成しているため、repo 名付き GitHub Pages URL 配下でも壊れにくい構成です。

## GitHub Actions 自動 deploy の仕組み

`.github/workflows/deploy.yml` で GitHub Pages の標準 Actions 構成を使っています。

- `actions/checkout@v4`
- `actions/configure-pages@v5`
- `actions/upload-pages-artifact@v3`
- `actions/deploy-pages@v4`

ビルド工程は入れていません。静的ファイルをそのまま Pages 用 artifact として deploy します。

## 既知の制約

- 映像入力の取得可否はブラウザ権限と OS デバイス状態に依存します
- 推奨入力は OBS 仮想カメラの 16:9 です
- USB キャプチャ直取りでは 640x480 などの 4:3 で取得される場合があります
- 16:9 入力では左右クロップを固定プリセットで扱います
- 4:3 入力でもアプリ側で補正して利用できますが、初期クロップの合わせ直しは必要です
- 自動 snap は 16:9 入力専用で、4:3 入力では `auto status` に待機理由だけを表示して監視は走りません
- キャプチャデバイスが別アプリに占有されていると開始できないことがあります
- 検索は完全一致優先で、曖昧検索や別名補完は入れていません
- CSV にないポケモン名は表示できません
- 左右クロップの初期位置は一般的な対戦画面を想定した仮置きなので、最初に手動調整が必要です
- 自動 snap は小さいテンプレート画像との照合で判定しているため、UI の見た目や位置が変わるとテンプレートの差し替えや ROI の再設定が必要です
- fallback は待機タイマー候補を保持できた場合だけ使うので、`VS` や `選出完了` ラッチ中の誤発火は避けやすい一方、待機タイマー自体を見逃した場合は fallback しません
