# pokemon-SnapCrop

`pokemon-SnapCrop` は、対戦画面のライブ映像をブラウザで見ながら、右側に敵パーティ領域だけを縦長クロップ表示し、下段の CLI 風パネルでポケモン情報を引ける静的 Web アプリです。

## できること

- 映像入力デバイス一覧を表示して、キャプチャデバイスや OBS 仮想カメラを選択する
- ライブ映像の上に敵パーティ用クロップ矩形を重ねて、ドラッグ移動と右下ハンドルで調整する
- 調整した領域を右側の縦長プレビューへ追従表示する
- 下段の CLI 風パネルでポケモン名を検索し、CSV からタイプ、特性、種族値を表示する
- クロップ位置とサイズを `localStorage` に保存し、次回起動時に復元する
- PWA としてインストールしやすい最低限の構成で動かす
- OBS 仮想カメラの 16:9 入力を優先し、4:3 入力でも黒帯込みで補正して扱う

## 対応環境

- Windows 11
- Microsoft Edge
- Google Chrome
- GitHub Pages または localhost 経由の配信

## ローカルでの起動方法

`file://` 直開きではなく、ローカルサーバー経由で開いてください。

- Visual Studio Code の Live Server など、任意の静的ファイルサーバーでこのフォルダを配信します
- 配信後、表示された `http://localhost:xxxx` を開きます

要点は「このリポジトリを HTTP 経由で配信すること」で、サーバーの種類は問いません。

## なぜ `file://` ではなくローカルサーバーが必要か

- `getUserMedia()` による映像入力は、基本的にセキュアコンテキストが必要です
- CSV は `fetch()` で読み込むため、`file://` 直開きだとブラウザ制約で失敗しやすいです
- Service Worker と PWA 登録も `file://` では正しく動きません

`localhost` または GitHub Pages のような HTTPS 配信を前提に使ってください。

## 映像デバイスの選択方法

1. ページを開く
2. `映像入力` からキャプチャデバイスまたは OBS 仮想カメラを選ぶ
3. `映像を開始` を押す
4. 初回はブラウザの映像アクセス許可を求められるので許可する

権限許可前はデバイス名が generic な表示になることがあります。許可後に `一覧更新` を押すと実デバイス名が見えやすくなります。
OBS Virtual Camera が見えている場合は、その入力を優先して使うのが推奨です。

## 敵側クロップ領域の調整方法

- ライブ映像上に赤い矩形が表示されます
- 矩形全体をドラッグすると移動します
- 右下ハンドルをドラッグするとサイズ変更します
- `X / Y / 幅 / 高さ` の数値入力でも微調整できます
- 右側プレビューは現在フレームに追従して更新します

座標計算は表示サイズ固定ではなく、実際の `videoWidth / videoHeight` を基準にしています。
4:3 入力時は左右の黒帯を含む表示でも、実映像領域に合わせてクロップ座標を補正します。

## CLI パネルの使い方

- 入力欄にはポケモン名だけを入れます
- Enter または `検索` ボタンで実行します
- 検索は CSV 内の `ポケモン名` 列に対して完全一致優先です

表示例:

```text
> ドラパルト
タイプ: ドラゴン / ゴースト
特性: クリアボディ / すりぬけ / のろわれボディ
種族値: H88 A120 B75 C100 D75 S142
```

## CSV の前提

同梱 CSV `data/champions_ Reg_M-A.csv` を読み込みます。実装では以下の実列名を確認して、そのまま利用しています。

- `ポケモン名`
- `タイプ1`
- `タイプ2`
- `H`
- `A`
- `B`
- `C`
- `D`
- `S`
- `とくせい1`
- `とくせい2`
- `とくせい3`

CSV の内容を勝手に推測せず、上記列の存在を読み込み時に検証しています。

## `localStorage` に保存する内容

- 敵パーティ用クロップ矩形の位置
- 敵パーティ用クロップ矩形のサイズ

保存時は現在の映像解像度に対する比率で保持し、次回起動時はその時点の映像サイズに合わせて安全に補正して復元します。

## PWA について

- `manifest.webmanifest` と `sw.js` を含む最低限の PWA 構成です
- アプリシェルと同梱 CSV をキャッシュします
- ただし、カメラ機能がオフラインでも完全動作することを保証するものではありません
- 目的はオフライン完全対応ではなく、アプリ風に起動しやすくすることです

## GitHub Pages への公開方法

1. このリポジトリを GitHub に push する
2. リポジトリの Pages 設定で `GitHub Actions` をソースにする
3. `main` ブランチへ push すると自動で deploy が走る

相対パスで構成しているため、repo 名付き GitHub Pages URL 配下でも壊れにくい構成です。

## GitHub Actions 自動 deploy の仕組み

`.github/workflows/deploy.yml` で GitHub Pages の標準 Actions 構成を使っています。

- `actions/checkout@v4`
- `actions/configure-pages@v5`
- `actions/upload-pages-artifact@v3`
- `actions/deploy-pages@v4`

ビルド工程は入れていません。静的ファイルをそのまま Pages 用 artifact として deploy します。

## 既知の制約

- 映像入力の取得可否はブラウザ権限と OS デバイス状態に依存します
- 推奨入力は OBS 仮想カメラの 16:9 です
- USB キャプチャ直取りでは 640x480 などの 4:3 で取得される場合があります
- 4:3 入力でもアプリ側で補正して利用できますが、初期クロップの合わせ直しは必要です
- キャプチャデバイスが別アプリに占有されていると開始できないことがあります
- 検索は完全一致優先で、曖昧検索や別名補完は入れていません
- CSV にないポケモン名は表示できません
- 右側クロップの初期位置は一般的な対戦画面を想定した仮置きなので、最初に手動調整が必要です
