# 技術・開発者向けガイド

通常の設定・操作は [README](../README.md) を参照してください。この文書では、内部処理、判定条件、診断方法、開発時の確認方法を扱います。

## 構成と使用技術

HTML / CSS / JavaScript による静的Webアプリです。バックエンドは持たず、映像の表示・切り出し・認識計算をブラウザ内で行います。名前推定用の比較画像・候補一覧とバトル統計は、利用者のブラウザから Pokémon Champions Battle Data へ直接取得します。

| ファイル | 役割 |
| --- | --- |
| [index.html](../index.html) / [style.css](../style.css) | 画面構造と表示 |
| [app.js](../app.js) | メディア入力、Canvasによる撮影、コマンド、auto snap、選出・瀕死・勝敗判定、ログ |
| [pokemon-icon-worker.js](../pokemon-icon-worker.js) | Web Workerによるアイコン画像の読み込み・認識 |
| [pokemon-icon-matcher.js](../pokemon-icon-matcher.js) | アイコンの前景抽出、候補探索、照合、採用判定 |
| [battle-api.js](../battle-api.js) | 外部データの取得、候補・統計の検証、同時通信数・再試行の制御 |
| [battle-statistics.js](../battle-statistics.js) | 統計の設定、コマンド候補、非同期のterminal表示 |
| [data/pokemon-display-catalog.json](../data/pokemon-display-catalog.json) | Showdown ID・フォーム分類・検索別名・日本語表示辞書 |
| [assets/auto/](../assets/auto/) | 画面判定用テンプレート画像 |
| [manifest.webmanifest](../manifest.webmanifest) / [sw.js](../sw.js) | PWA設定とService Workerによるキャッシュ |
| [tools/](../tools/) / [tests/](../tests/) | データ生成・検証、認識ベンチマーク、Nodeテスト |

映像と音声は `getUserMedia()` を使い、別の入力として管理します。OBS Virtual Camera は映像のみを前提とし、音声入力の変更で映像を再初期化しない構成です。撮影範囲、入力元、レイアウト、テーマなどの設定は `localStorage` に保存します。

ページ初期化時は開始ボタンと共通の開始処理を呼び、まず `getUserMedia({ video: true, audio: true })` で両方の権限をまとめて要求します。失敗した場合はカメラだけの要求へ1回切り替えます。取得中に機器一覧を更新し、権限取得用の全トラックは成功・失敗にかかわらず停止してから、選択した入力を通常の経路で開始します。カメラだけの取得へ切り替えた回は、音声を再要求せず映像だけで続行します。

保存済みの入力が許可後の一覧にあれば優先し、なければOBSまたは先頭の入力を使用します。開始中は開始・一覧更新・入力選択を無効にして重複要求を防ぎ、成功・拒否・失敗後に再操作できる状態へ戻します。一覧取得失敗・機器なし・非対応の場合は通常の映像再生へ進まず案内を表示します。同じページ内で権限取得と一覧更新が成功した後は、入力切り替えのたびに一括要求を繰り返しません。

通常の映像取得は `audio: false` で行い、音声入力が選択されているときだけ別ストリームで音声を取得します。`音声なし` の設定は保持し、権限取得に使ったマイクをそのまま再生しません。権限未取得で `deviceId` が空の音声入力には、空文字の `音声なし` と異なる一時的な選択値を使います。その入力の選択時は機器IDを指定せずマイクを要求し、取得後の実IDと機器名で一覧・保存値を更新します。一時値自体は保存しません。待機中に音声を変更・解除した場合、古い取得結果は停止して破棄します。

音声再生の `AudioContext.resume()` は、ユーザー操作待ちでも映像開始処理やterminalへのフォーカス復帰を止めないよう完了を待ちません。

Service Workerは画面本体と主要スクリプト・ローカル表示辞書を事前キャッシュします。同一配信元のページ遷移とApp Shellはネットワーク優先、それ以外の同一配信元GETはキャッシュ優先です。外部配信元のリクエストは処理・保存対象から外し、提供元のHTTPキャッシュ指定に任せます。更新時は `pokemon-snapcrop-` で始まる旧キャッシュだけを削除します。アプリ内の参照先はリポジトリ名付きURL配下で使える相対パスを維持します。

## 自動撮影と画面判定

通常のterminalログは撮影結果・エラー・操作案内を表示します。固定クロップの適用、撮影直前の検出過程、映像のみ取得への切り替え途中は `debug on` で確認できます。診断情報の記録・出力条件は [診断とログの保存](#診断とログの保存) を参照してください。

実装の中心は `app.js` の `AUTO_SNAP_CONFIG` と `runAutoSnapDetection()` です。ROIは画像内の認識対象範囲、HUDは対戦中のHPやポケモンなどを表示する部分を指します。

- 16:9入力を主経路とし、固定クロッププリセットを使用します。4:3入力ではクロップ補正は行いますが、自動認識は行いません。
- `auto on` は必要に応じて `ready` へ切り替えます。auto snapの監視は `ready` 中だけ行います。
- 読み込み画面 → 選出画面 → 待機画面の順に確認し、待機タイマーを優先して撮影します。選出完了の検出は補助として使用します。
- 読み込み画面の最終検出から6秒たっても選出を確認できない場合、復帰確認へ移ります。最終検出から30秒以内は、選出タイマーの2回連続一致で復帰します。
- 復帰確認中に戦闘HUDを2回連続で確認した場合、または期限を過ぎた場合は、次の読み込み画面を待ちます。
- 選出・待機画面はタイマーアイコンで判定します。砂嵐などのフィールド色だけで戦闘HUDの確認を止めないようにしています。

## 相手6匹の名前推定

相手参照画像の撮影後にバックグラウンドで名前を推定し、認識できない枠は未確定のままにします。16:9入力だけを対象とし、ランクマッチの選出画面内でパーティが変わっても誤採用を増やさないことを優先します。

### 候補データ

- API一覧に掲載され、ローカルの表示辞書で分類できる非メガの画像を候補にします。掲載自体をChampions用画像の条件とし、メガシンカ個体は自動推定候補から除外します。メガの名前・フォームと手入力での統計照会は表示辞書に残します。
- PNGはAPIが返す `image_path` を使います。Showdown IDから画像名を組み立てず、指定配信元の `/pokemon_champions_assets/pokemon/` 配下のPNGだけを許可します。未掲載の姿や未知のIDを、通常種・別ソースの画像へ推測で置き換えません。
- 必要な候補画像の取得に失敗した場合は、欠けた候補集合で名前を確定せず、名前推定を待機させます。`api retry` は失敗した読み込みを再試行します。取得画像やそこから作った比較用の特徴量は、そのページを開いている間のメモリで使い回します。
- 同梱する表示辞書は Pokémon Showdown のID・フォーム・進化・伝説区分と、damage-calc-ja-layerの表示APIから生成します。元コミットとファイルハッシュを `provenance` に記録し、翻訳が未確認の名前は英語を保持します。フォームの同一性は日本語名ではなくShowdown IDで扱います。

出典・ライセンスは [データ提供元・クレジット](../THIRD_PARTY_NOTICES.md) を参照してください。

### 照合と採用

`pokemon-icon-matcher.js` の `DEFAULT_MATCHER_CONFIG` が基本設定です。前景は、背景から切り出したポケモンの像を指します。

1. 各枠の前景を抽出し、形状・グレースケール・輪郭・色などを照合して粗い候補探索を行います。
2. 粗探索の1位は複数の前景切り出しで再確認します。通常閾値未満でも、複数由来のテンプレートによる裏付けと十分な候補差など、採用条件を満たす場合だけ名前を採用します。
3. 初回判定で未確定になった枠だけ、粗探索の後半候補と少し寛容な前景抽出を追加確認します。追加確認後も同じ信頼条件を満たさない名前は採用しません。

名前推定と、対戦中にどの枠が出たかの判定は別処理です。選出番号の判定は、撮影した相手パーティ画像と対戦中のHUDを比較し、外部の候補PNGを使いません。名前を推定できた枠の選出が確定すると、選択ルールのバトル統計をterminalへ表示します。

## 外部通信とバトル統計

`battle-api.js` を外部通信の共通入口とし、候補PNGのWorker読み込みもメインスレッドの通信キュー経由で行います。最大同時通信数は4、1回のタイムアウトは15秒です。同じ進行中リクエストは共有し、一時的な通信失敗だけ1回再試行します。429では `Retry-After` を尊重し、長い待機が必要なら操作可能なエラーとして戻します。自動ポーリングは行いません。`fetch` は `credentials: "omit"`、`mode: "cors"`、`cache: "default"` を使い、提供元による別サイトからの画素読み取り許可が必要です。

API一覧から保持するのは識別子、画像URL、統計との明示的な対応、掲載ルール、データ版などです。統計は `/api/battle/<Singles|Doubles>/<Showdown ID>` の最新データだけを使い、種族値などの種族データとして扱いません。Cache API・IndexedDB・localStorageへ取得画像、生統計、API一覧を保存しません。 旧版Service Workerが制御中の場合は、外部通信を保存しない新版へ切り替わったことを確認してから外部取得を開始します。設定以外の情報はページ終了時に失われ、次回取得時は通常のHTTPキャッシュに従います。

認識したフォームIDと統計のIDは別に管理します。提供元の `battleName` / `pokemonPages` に明示された対応だけを使用し、フォーム接尾辞を削って通常種へ落とす推測はしません。統計が共通なら「統計: ○○と共通」と表示します。APIに最新統計がないルール、404、通信失敗、不正な応答は区別します。

### 表示設定と名称

- 内部の項目は `move` → 技、`ability` → 特性、`held_item` → 持ち物、`stat_alignment` → **性格**。率はAPIの値を小数1桁で表示し、再正規化しません。
- 初期ルールは未選択。最初の候補からTab/Shift+Tabで選んでEnterで確定、Escで保留できます。`stats rule` で再表示します。
- 初期件数は技5・特性all・持ち物5・性格3、最低使用率0。各項目は最低使用率以上で絞り、提供元の順位順に上位件数を表示します。件数は1以上の整数または `all`、最低使用率は0〜100です。
- `stats show` の指定順に項目を表示します。掲載項目なしと、足切り後の空欄を別の文言にします。手入力検索は名前・別名・Showdown IDをローカル辞書で解決し、同じ統計表示を使います。
- 翻訳はポケモン・技・特性・持ち物・性格の各辞書を使います。確認済みの日本語がない場合は元の英語名で表示し、独自の推測訳を作りません。

### 非同期表示と記録

名前が確定した枠の統計を先読みし、選出確定時には取得中表示を同じ表示枠で更新します。自動表示には選出番号・ルール・統計の日付・取得日時を付けます。ルールや件数などの変更は現在の撮影に紐づく自動表示へ反映し、手入力や過去の撮影の表示は当時の設定を維持します。

撮影ID・試合ID・相手枠・選出番号・フォームID・設定更新の番号を使って遅延応答を確認します。撮り直し、手動の選出訂正、ルール変更、terminalクリア後に古い応答で表示を戻しません。terminalをクリアした後は、同じ選出を毎フレーム再表示しません。表示更新は入力フォーカスを奪わず、上へスクロールしている間の位置も維持します。

試合ログにはルール、フォームID、統計ID、読み込み状態、データ日付などの小さな診断情報を残します。生の統計応答や比較候補PNGは書き出しません。完了済み試合へ遅れて結果を追記せず、現在の画像の所属試合と一致した記録だけを更新します。

## 選出・瀕死・勝敗の判定

- 対戦HUDから相手の実選出を確認し、相手参照画像へ `１` `２` `３` `４` の選出バッジを重ねます。
- 戦闘HUDの確認条件を満たさない場合でも、相手HUDが高信頼で一致した場合のみ、補助的に選出バッジを付与します。条件は `PICK_OVERLAY_CONFIG` と `updatePickOverlayDetection()` を参照してください。
- AUTOがONの間、相手HUDから瀕死を検出すると該当枠を暗く表示します。`faint reset` で解除します。
- 戦闘HUD確認後、勝敗画面の金色モンスターボールを検出すると、`[result] WIN` / `[result] LOSE` を1試合1回だけterminalへ表示します。通常の勝敗演出がない通信切断などは判定できません。

## 診断とログの保存

通常の利用では `debug on` は不要です。問題の調査時に以下のコマンドを使用します。

| コマンド | 内容 |
| --- | --- |
| `debug on` | 認識範囲の表示と、勝敗判定・名前推定・処理時間などのデバッグ表示を有効にします |
| `debug off` | デバッグ表示を無効にします |
| `debug status` | デバッグ状態と、保存対象に指定できる試合ログの番号を確認します |
| `auto status` | 自動撮影の状態を表示します。`debug on` 中は選出の時間切れ・復帰の履歴も表示します |
| `debug log export` | 記録中の試合ログをTXTで保存します。記録中の試合がなければ直近の記録を保存します |
| `debug log export <番号>` | `debug status` に表示された番号の試合ログを保存します |
| `debug icon export` | 現在の相手画像、6枠のROI、名前推定の診断情報を含むJSONと、同名のPNGを保存します |

TXT・JSON・PNGの出力は `debug off` でも利用できます。試合ログは自動で永続保存されないため、ページを閉じたり再読み込みしたりする前に出力してください。相手画像をまだ撮影していない場合、`debug icon export` は画像を出力できません。

### JSON・PNGの扱い

PNGはJSONに含まれる相手参照画像と同じ元画像です。選出番号・瀕死の暗転・デバッグ表示は含みません。JSONとPNGは拡張子だけが異なる同名で出力します。

提供元から取得した候補PNGはJSON・PNGへ同梱しません。比較に使った提供元・版・ID・画像URLや特徴の識別情報は診断に使いますが、出力する画像は利用者が撮影した参照画像とROIだけです。

2ファイルの保存がブラウザにブロックされた場合は、このサイトの複数ファイルの自動ダウンロードを許可してから、再度 `debug icon export` を実行してください。

### 試合と撮影の識別

試合の記録開始時に固定の試合IDを発行し、TXT・JSON・PNGのファイル名に記録開始UTC時刻と試合IDを含めます。出力ごとの連番、撮影ごとの `captureId` と撮影時刻も記録します。

画像は撮影時の所属試合を保持します。前試合の画像を後から出力しても、現在の試合へ付け替えません。所属不明の画像は `unlinked` として区別します。同じ試合のTXTとJSON・PNGを照合する際は、操作用の試合番号だけでなく、試合IDと撮影IDを確認してください。

### 選出バッジの診断記録

`debug off` でも、比較停止理由、HUD品質、実比較時の6枠のスコア・位置補正・候補採用条件・連続一致・採番結果を試合ログへ記録します。手動修正やリセット、名前・データ待ちから情報表示までの状態変更も対象です。

詳細比較は7,200回、採番関連イベントは256件を上限として古いものから置き換えます。待機理由の秒単位集計や理由別の回数・最初と最後の例は別に保持します。前試合の画像や所属不明の画像は集計を分離し、記録終了後の結果を完了済み試合へ追記しません。長時間の調査では、詳細が残っている間にログを出力してください。

### 瀕死判定の診断記録

`debug off` でも、瀕死判定を実行した回ごとにHUD左右2枠の診断情報をTXTへ残します。判定間隔・条件・連続一致回数は `FAINT_DETECTION_CONFIG` に従い、記録のための追加画像読み取りは行いません。

- **瀕死診断の設定・集計**: 実行時の判定条件と読み取り範囲、理由コードの説明、HUD別の観測・確定回数、理由別・画像所属別の回数、各理由の最初と最後の例。
- **瀕死イベント**: 対象や対応元の変化、条件不成立、確定待ち・確定済み・今回確定、待ち状態の保持・期限切れ、リセット、手動採番・解除に伴う状態変更。同じ状態の繰り返しは詳細判定へ残し、イベントは変化時を中心に記録します。
- **瀕死の詳細判定**: アイコン・背景・％表示の各範囲について赤・ピンク・白・暗い画素の割合と明るさ、実際の画素座標、各条件の成立、判定前後の一致回数、対象枠、今回の照合候補、以前の対応とその経過時間。

`resolved.source` は `live`（今回の照合）、`cache`（以前の対応）、`cache-live-weak`（弱い別候補より以前の対応を優先）、`pending`（一致待ちの対象）、`missing`（対応不明）を区別します。`currentRequiredStreak` は現在の信号と対応元から求めた必要回数、`decision.requiredStreak` は保持中の状態を含め実際に使った必要回数です。

`percentVisible` は白い画素が一定量あるかの確認で、数字の「0%」の認識ではありません。`assets/auto/faint-roi-samples` の画像は実行時の照合テンプレートとして読み込みません。画像を差し替えるだけでは判定は変わりません。

瀕死の詳細判定は最新7,200回、関連イベントは最新256件を独立して保持します。古い詳細を省略しても、全体集計と各理由の最初・最後の例は保持し、省略件数をTXTに出力します。採番の詳細や試合イベントの保存枠を消費しません。記録終了後は完了済みの記録へ追記しません。

各行には現在の試合ID・対象画像の所属試合ID・撮影ID・UTC時刻を付けます。`matchElapsedMs` は試合の記録開始からの経過ミリ秒、`ageMs` は以前の対応や一致待ちが最後に観測されてからの経過ミリ秒です。`refIndex` は相手画像の上から0〜5、`hudIndex` は対戦HUDの左0・右1、`null` は未取得・未確定です。前試合・所属不明の画像の結果は現在の試合画像の成績と分けて集計します。

### 瀕死の誤爆と不発を採取する手順

1. 通常どおりAUTOで使用し、問題が起きた前後数秒の録画を残します。難しければ対戦HUDの左右全体が写った画像を残します。小さな％表示だけでなく、アイコン・背景も必要です。アプリは動画や問題発生時の画像を自動保存しません。
2. 次の試合へ進む前に `debug log export` と `debug icon export` を実行し、同じ試合IDのTXT・JSON・PNGを保存します。画面をリセットする場合も、その前に保存してください。名前推定用のPNGは撮影済みのパーティ画像で、瀕死発生時の対戦画面ではありません。
3. 録画・画像を同じ試合IDと対応づけ、「録画の00:42、相手左、上から3枠目、HPが残っているのに瀕死表示」のように発生位置・時刻・正しい状態を短く添えます。録画内の経過時刻とログのUTC時刻は別なので、区別して記載してください。不発は実際に倒れた時刻、正常例は正しく表示された時刻を残します。

誤爆・不発に加え、正常に動いた場面も少数採取します。数値ログはアプリが何を根拠に判断したかを示し、録画・正解メモは実際の状態を確認するために使います。保存したTXTに含まれない診断情報は、後から復元できません。

## 開発時の実行と確認

ローカルではVS CodeのLive ServerなどでリポジトリをHTTP配信し、`localhost` で開きます。`file://` 直開きには対応しません。メディア入力・表示辞書読み込み・Service Workerのため、localhostまたはHTTPSを前提とします。

リポジトリのルートで、変更内容に応じて以下を実行します。

```sh
# Nodeテスト
npm test

# 同梱表示辞書の再現性を検証（生成元の準備が必要。生成物は書き換えない）
npm run validate:catalog

# 同梱表示辞書の再現性検証とNodeテスト（生成元の準備が必要）
npm run check

# 公開するファイルだけをdistへ組み立てる
npm run build:pages

# 構文検査の例。実際に変更したJavaScriptファイルを指定する
node --check app.js

# 差分の空白エラーを確認
git diff --check
```

本体の実行・公開ビルド・通常のNodeテストには、コミット済みの表示辞書とライセンスを使います。生成元リポジトリやローカルの参考資料は不要です。公開ビルドと通常のNodeテストは外部通信も必要としません。

表示辞書の変更時は `npm run generate:catalog` を使い、生成物を直接編集しません。再生成と再現性検証（`validate:catalog` / `check`）には、Node.js 24以上と、別途用意した Pokémon Showdown・damage-calc-ja-layer のソースが必要です。Showdown本体のコミットと日本語レイヤーが参照するコミットを一致させます。生成ツールは読み込み先を固定しているため、準備するソースの配置は [生成スクリプト](../tools/generate-display-catalog.mjs) の `showdownRoot`・`localeRoot` とライセンス読み込み先を確認してください。辞書とShowdownのライセンス文を生成・検証します。

GitHub Pagesには `tools/build-pages.mjs` の許可リストで作成した `dist` だけをアップロードします。配布対象は画面・スクリプト・表示辞書・ライセンス・画面検出テンプレート・UI素材です。開発用ツール・参考資料・診断ログ・録画は配布対象外です。リスト外の新しい実行時ファイルを追加した場合は、公開物の検査も更新します。Service Workerの版はアプリ・ベンチマークと同期します。

認識結果に影響する変更では、HTTP配信した [アイコン認識ベンチマーク](../tools/pokemon-icon-benchmark.html) で対象サンプルと既存サンプルを比較し、誤採用が増えていないか確認します。表示・操作の変更ではブラウザで対象操作とterminalのフォーカスを確認し、レイアウト変更なら狭い幅・fullscreen・PWAへの影響も確認します。
